# Game builder: run settings

V41 first editor, accepted scope: saved guard speeds/vision/attack timings, reinforcement frequency, loot amounts and search times, with defaults reset. Sprite import and room editing come later.

Open the private local server admin link from Terminal. Select a lair, change numbers and click Save settings for next run. No extra installation or public/gameplay editing controls. The screen uses the existing admin buttons, layout, status and backup system. All fifteen fields come from src/tuning.js; that same list defines labels, bounds, defaults, validation and mapping to the real rules. Chances display as percentages; the server stores fractions. Inputs are keyboard accessible and polling preserves unfinished edits in the same lair. Switching lairs loads that lair's saved values. Reset settings to defaults saves immediately and clears any unsaved draft.

Implementation defaults: settings belong to a lair, editable only through private server admin. New groups and older saves use existing balance defaults. Save during a run is allowed: the dungeon copies a complete independent settings object at departure; existing positions, combat, search reservations, loot and bags are untouched. New arrivals see that run's settings. The next departure uses the latest saved values. Multiple groups can have different values and run concurrently. Solo uses the same shared functions with their previous default values.

Editable: patrol/chase/search speeds; normal/alerted sight distances; notice time; attack windup/recovery; whole alerts per extra guard; chest/cupboard/crate search durations; empty-search chance near/far; two-item chance conditional on a nonempty roll. Heat continues to increase chase speed up to its existing ceiling, or retains a manually set speed above that ceiling without slowing it. Personal search bonuses divide the edited duration; difficulty keeps its extra guards/rare/value bonuses. Loot is rolled once at generation, with distance blending unchanged. Guard vision rendering and reinforcement progress use the active run values.

Tuning is durable lair metadata in payload2, included in SQLite checkpoints/full backups. Old saves/backups without tuning use defaults; invalid present settings reject loading/restoring rather than silently replacing them. Settings updates validate the entire field set and bounds before backing up or mutating. Every save/reset makes the existing full before-change backup, then checkpoints; backup failure prevents edits and disk-write failure latches the hub closed. Reset lair/goblin/all progress retains tuning; Reset settings is the explicit balance reset. Full restore restores the backed-up tuning (old backups use defaults). Stock/progress/restore locks still apply while runs are active, independently of the allowed next-run settings edit. No new database schema or dependency.
